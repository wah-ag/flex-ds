### Check 1: Fields present (pass)

All seven keys are present: `use_when` (7 entries), `dont_use_when` (6),
`variant_intent` (`category`, `size`, `state`), `placement` (empty),
`pairs_with` (2), `required_tokens` (36), and `a11y` (2). Every non-empty
entry has a `source`, and `use_when` is not empty. The `pairs_with`
citations (`DescriptionItem.jsx:3`, `JobPosition.jsx:2`) each import Label at
the commit.

### Check 2: Every `dont_use_when` names an alternative (warning)

Unchanged from the `c43f0ac` review. None of the six entries names what to
use instead. All six come from
`Figma 71:2279 (Label Doc Frame › Don’t, text I71:2279;2406:416;71:2278)`:

1. "Don’t use labels for long sentences or large amounts of information."
2. "Don’t use too many labels within a single component or section."
3. "Don’t use color as the only way to communicate meaning."
4. "Don’t mix inconsistent sizes, styles, or shapes for labels with the same purpose."
5. "Don’t use labels as buttons unless they are designed and documented as interactive."
6. "Don’t use decorative labels that do not provide meaningful information."

This review suggests no alternatives.

### Check 3: `a11y` specific, not generic (pass)

- "Renders a <span> with no role or aria attributes of its own." (source: `src/components/Label/Label.jsx:26`). At the commit, `<span` is at line 26. It gets `{...rest}` (line 27), `className` (lines 28-30) and `data-state` (line 31), and no `role` or `aria-*` of its own.
- "The icon is aria-hidden=\"true\" and focusable=\"false\"." (source: `src/components/Label/Label.jsx:34`). At the commit, the icon with both attributes is at line 34.

Both citations point at the line they describe. The off-by-one ruling is not
needed.

### Check 4: `required_tokens` resolve (pass)

- The `var(--…)` references in `Label.css` and `Label.jsx` give 36 unique tokens, not counting the component's own `--label-icon-color` custom property. `required_tokens` lists 36. The two sets are identical (`diff` is empty).
- All 36 are defined in `build/css/*.css` at the commit. The four added by #140 (`--background-neutral-disable`, `--background-neutral-surface`, `--icon-neutral-primary`, `--text-neutral-primary`) are in `tokens.css` and `tokens-dark.css`.

### Check 5: All variants covered (pass)

The code accepts three variant props: `category` (`brand`, `info`,
`success`, `error`, `warning`, `normal`), `size` (`lg`, `md`, `sm`) and
`state` (`idle`, `hover`). Every value is a key in `variant_intent`.

These meanings are `null`, which counts as covered (there is no Figma text):
all six `category` values, all three `size` values, and both `state` values.

These props are not counted as variant props: `labelText` (text),
`showIcon` (boolean), `swapIcon` (instance swap), and `className` and
`...rest` (DOM pass-throughs).

### Check 6: No two components claim the same job (pass)

No intent file other than Label's changed since the `c43f0ac` review
(`git diff --stat c43f0ac 1d42708 -- 'src/components/*/*.intent.json'`), and
#140 did not change Label's `use_when`. So the comparison in the `c43f0ac`
report still holds. These are the nearest entries, and none of them is a
finding:

- Label: "Use labels to provide short, meaningful contextual information." (`Figma 71:2279 (Label Doc Frame › Do, text I71:2279;2406:461;71:2275)`)
- NavLabel: "used as a header navigation label" (`Figma 55:34 (Header/NavLabel component description, paragraph 1, first clause)`)

  NavLabel is about header navigation, and Label is about contextual information on content.

- Label: "Keep label text concise and easy to scan." (Figma 71:2279, as above)
- TextField and PasswordField: "Keep labels, helper text, and validation messages concise and clear." (`Figma 71:2194 (Input Field Doc Frame › Do, text I71:2194;2406:461;71:2190)`)

  The input fields' "labels" are their own field labels, not the Label component.

- Label: "Maintain consistent padding, height, typography, and spacing." (Figma 71:2279, as above)
- CardContainer: "Maintain consistent spacing, padding, and alignment across similar cards." (`Figma 69:1498 (Cards Doc Frame › Do, text I69:1498;2406:461;69:1495)`)

  Each entry is about consistency within its own component.

- Label: "Use the appropriate variant to communicate different meanings or statuses." (Figma 71:2279, as above)
- ButtonCTA: "Use the correct usage variant for the intended interaction and context." (`Figma 17:826 (Buttons Doc Frame › Do, text I17:826;2406:461;17:822)`)

  Each is about choosing a variant within its own component.
