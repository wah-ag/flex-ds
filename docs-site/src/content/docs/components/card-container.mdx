### When to use

- Cards also contain other components in slot area.
- Cards can serve as entry points into deeper levels of detail or navigation, such as a music album or details on an upcoming vacation.
- Contents can include anything from images to headlines, supporting text, buttons and lists.
- Use cards to display contents and actions on a single topic.
- Cards should be easy to scan for relevant and actionable information.
- Maintain consistent spacing, padding, and alignment across similar cards.

### When not to use

- Don’t scroll within a card to reveal information.
- Don’t use multiple competing CTAs within a single card.
- Card shouldn’t contain that can be swiped, such as image carousel or pagination. Also, swipe gestures shouldn’t cause portions of cards to detach upon swiping.
- Don’t create inconsistent card sizes, spacing, or layouts for similar content.
- On a mobile device, cards can’t internally scroll, as it could use two scroll bars to be displayed.
- Don’t make the entire card clickable unless the whole card represents a single action.
- Don’t let cards bump other elements out of the way. When a card is picked up, it appears in front of all elements, except app bars and navigation.

three variants: `state=idle` (36:157), `state=hover` (36:159) and
`state=active` (36:169). Each variant holds one slot, `card slot`. It is
built on `component/card-container` and composes no other component.

Figma has no `size` property, and CardContainer has no `size` prop.

**Owner ruling on the slot name (2026-10-15)**

| Figma name | Prop | Ruling |
| --- | --- | --- |
| `card slot` | `cardSlot` | Owner ruling 2026-10-15: `card slot` → `cardSlot`, the literal camelCase of the Figma name, chosen over `children`. A JavaScript prop name cannot contain a space, so the space is dropped and the next word capitalised. `children` is not part of the API: it is neither rendered nor passed to the root `&lt;div&gt;`. |

**Not from Figma**

Any HTML attribute (`id`, `role`, `aria-*`, `onClick`, ...) passes through
to the root `&lt;div&gt;`. `className` is appended to the component's own class.

Figma's stroke is inside the frame and the slot moves in with it (17,13 at
the default width, 18,14 at the selected width), so the padding grows by the
stroke width.

The hover stroke width was bound to the core primitive `border/width/lg`
in an earlier version of the node. The Designer rebound it to
`border-width-default` before this build.

**Owner rulings (2026-10-04)**

1. **Width.** Figma's card is a fixed 514 bound to no token. That is not a
   gap. The card fills its container; the stories frame it at 514.
2. **States.** Only idle, hover and active are designed. Focus, pressed and
   disabled are skipped for now, not forgotten.

**Behaviour**

- `hover` comes from a real pointer over an idle card. Passing
  `state="hover"` pins the look, for review.
- `active` is held by the product (the card the user has chosen) and is set
  with `state="active"`.
