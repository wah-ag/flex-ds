## Branches

- `main` is production and receives only `staging`.
- `staging` receives component branches by pull request. A human merges them.
- Work happens on a branch such as `component/<name>`, never on `main`.

## Tokens

- `tokens/` is the Figma export. Never hand-edit it; fix the value in Figma, re-export and rebuild.
- `build/` is generated by `npm run build:tokens`. Never edit or commit it.
- A token sync is committed on its own, with `tokens/` staged alone.

## Components

- One folder per component in `src/components/`, in PascalCase, with its stories beside it.
- Every visual value references a token. Components use semantic tokens only, never raw hex, px or font values.
- Prop names match the Figma property names exactly. A name that must change is written up under `docs/` for review, not renamed silently.
- Every variant and every state has a story. Stories read the token list from `build/css/*.css`, never from a hand-kept list.
- Import a component; never copy its styles into another. Parts used in more than one place become their own subcomponent.
- Icons come from `lucide-react` only, sized with the `size-icon-*` tokens and coloured through `currentColor`.

## Commands

| Command | What it does |
| --- | --- |
| `npm install` | Installs dependencies. |
| `npm run build:tokens` | Rebuilds `build/` from `tokens/`. |
| `npm run check:tokens` | Reports mode gaps and opaque `a`-suffixed tokens. |
| `npm run storybook` | Rebuilds tokens, then runs Storybook on port 6006. |
| `node scripts/security-check.mjs` | The security gate for build output. |
